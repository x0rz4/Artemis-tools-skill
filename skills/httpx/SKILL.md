# HTTP 探活与技术识别

适用版本：**httpx 1.12.0**；工具包支持 Linux amd64 / arm64。参数与字段依据见 [固定版本来源](references/sources.md)。

## 调用准备

首次调用先读 [Artemis 调用约定](references/artemis.md)，确认当前工具 key、schema、启用状态和版本。这里的命令是 CLI 参考，不能直接塞进 `{args}` 薄封装。

输入为已确认范围的域名、IP:port 或完整 URL，一行一项。优先保留已知 scheme 和非标准端口；同一 IP 的不同域名可能对应不同虚拟主机。准备存在的输入文件和本次独立的可写输出目录。

## 选择参数

| 参数 | 用途与取舍 |
| --- | --- |
| `-l` / `-u` | 文件输入 / 单个或多个目标 |
| `-sc -title -td` | 状态码、标题、技术指纹；指纹是线索，不是漏洞证明 |
| `-json -o` | JSONL 文件，便于后续提取 URL |
| `-rl` / `-t` | 每秒请求上限 / 并发线程；遵循任务限额 |
| `-timeout -retries` | 单次超时秒数 / 失败重试次数 |
| `-duc` | 关闭二进制更新检查 |

基础探活示例，替换文件路径后再按实际工具 schema 调用：

```bash
httpx -l /work/hosts.txt -sc -title -td -json -o /work/run-001/httpx.jsonl -rl 10 -t 5 -timeout 10 -retries 1 -duc
```

首次保留各类 HTTP 状态码；401/403 表明存在响应，不能当作主机不存在。需要重定向时先确认跳转目标范围；不要为了收集更多资产自动扩展到响应中出现的域名。常规探活无需截图浏览器，也无需保存完整响应体。

## 解释结果

逐行解析 JSON 对象，重点读取 `input`、`url`、`status_code`、`title`、`tech`、`host`、`port`、`failed`；可选字段缺失不等于空字符串或否定结论。保留原文件，并输出 URL、状态、标题和技术信息的简表，避免把完整日志灌入上下文。

按最终 URL 去重，但保留输入与输出的映射。向 katana 交接通过范围过滤的 URL；向 nuclei 交接时另外选择相关模板，不能将技术识别直接写成已确认漏洞。

## 故障与停止

- 命令显示 Python 包帮助：工具路径解析错误，回到已注册二进制配置，不重新安装同名包。
- `unknown flag`：先核对版本与参数边界；若整段参数被当成一个参数，按调用约定处理，不能靠增减引号重试。
- DNS、TLS 或超时：记录失败目标，降低并发或在任务预算内调整超时，仅补试失败子集一次；不要自动改用范围外代理。
- 429、持续 5xx 或相同错误再次出现：停止该批，报告限流/失败比例与已完成覆盖。

输出文件为空时同时检查退出状态、输入数量与错误流，分别报告“没有成功响应”和“执行失败”。
