# 被动子域发现

适用版本：**subfinder 2.17.0**；Linux amd64 / arm64。依据见 [固定版本来源](references/sources.md)。

## 调用准备

先读 [Artemis 调用约定](references/artemis.md)。输入是域名，不带 scheme、端口或路径。被动发现会访问第三方数据源；确认这些来源符合任务的网络条件。需要 API Key 的来源使用部署端已有 provider 配置，不能将密钥写入 Skill 或结果摘要。

## 选择参数

| 参数 | 适用情况 |
| --- | --- |
| `-d` / `-dL` | 单域名 / 域名文件 |
| `-s` / `-es` | 选择 / 排除指定数据源 |
| `-ls` | 查看当前版本支持的数据源 |
| `-pc` | 指定已有 provider 配置文件 |
| `-oJ -cs -o` | JSONL、记录来源集合、输出路径 |
| `-rl -timeout -max-time` | 全局请求速率、请求超时秒数、发现时限分钟数 |
| `-active` | 额外执行活动解析；仅需被动清单时不添加 |

```bash
subfinder -d example.com -oJ -cs -o /work/run-001/subfinder.jsonl -rl 5 -timeout 15 -max-time 2 -duc
```

`example.com` 是替换占位值，不能作为本次真实目标。批量使用 `-dL /work/domains.txt` 替代 `-d`。不要默认加 `-all`；数据源增加会改变耗时、限流和所需凭据。

## 结果处理

逐行读取 `host`、`input`；本示例 `-cs` 对应来源数组 `sources`，没有该开关的输出可能使用单个 `source`。发现记录可以过期，不能据此标记端口开放或 HTTP 存活。

统一域名大小写、去掉末尾点后去重，同时保留来源。对于根域名范围，只接受该根域本身或以 `.` 加根域结尾的域名，避免把 `notexample.com` 当作 `example.com` 子域。明确排除项继续生效。

将范围内域名写成独立列表，按任务需要交给 httpx 探活；只有任务包含端口探测时才交给 naabu。

## 故障与停止

- 来源返回认证错误：报告具体来源和配置缺失，不打印 API Key、不自动搜集凭据。
- 429 或来源超时：降低速率，必要时排除失败来源并记录覆盖缺口，最多补试一次；不把部分来源失败写成全量发现成功。
- 没有输出：核对输入格式、可用来源和错误流；报告“本次来源未返回记录”，不声称域名没有子域。
- 域名记录过多：先按范围过滤、去重和汇总数量，再抽取少量示例，完整结果保留文件。
