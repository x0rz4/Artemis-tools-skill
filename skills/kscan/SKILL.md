# 端口与协议指纹识别

适用版本：**kscan 1.85**；当前锁文件只提供 **Linux amd64**。arm64 上停止并报告不支持，不以 Skill 可加载推断二进制可运行。依据见 [固定版本来源](references/sources.md)。

## 调用准备

先读 [Artemis 调用约定](references/artemis.md)。kscan 的 **`-t` 是目标，并发是 `--threads`**；不要套用 fscan/httpx 的 `-t` 语义。输入可以是 IP、带端口的资产或 URL，应保留原有端口和路径。

明确需要识别的资产与端口。默认端口集合较大，并发默认也较高，应在调用中显式收窄。文件输入使用 `-t file:/work/targets.txt`，没有通用的 `-l` 文件参数。

## 参数与示例

| 参数 | 含义 |
| --- | --- |
| `-t` / `--target` | 探测目标 |
| `-p` / `--port` | 端口集合或区间 |
| `--threads` | 并发数量 |
| `--timeout` | 超时秒数 |
| `-Pn` | 关闭智能存活探测；已知目标被发现阶段漏掉时按需使用 |
| `-Cn` | 关闭颜色输出 |
| `-oJ` | JSON 输出文件名，不能当作无值开关 |

```bash
kscan -t 192.0.2.10 -p 80,443,8080 --threads 5 --timeout 3 -Cn -oJ /work/run-001/kscan.json
```

`192.0.2.10` 是文档占位地址，替换为实际范围内目标。仅识别资产时不启用 `--hydra`、`--spy`、FOFA 查询或额外数据下载；这些是不同任务和依赖，不能由“抓取指纹”默认推导。

## 解释结果

`-oJ` 写出 **JSON 数组**，每个元素是字符串键值映射；不要按 JSONL 或其它工具的小写字段结构解析。固定入口字段是大写的 `URL`、`Keyword`，还可能有 `Service`、`Title`、`Length`、`Response` 等字段。先查看少量对象的真实键名，数值字符串需要校验后转换；缺少字段时保留缺失，不猜值。摘要只选必要字段，避免加载完整 Response。

读取完成的文件，不把运行中被写入的数组当作最终结果。此版本写文件没有统一截断旧内容，使用每次独立的新文件路径；不要重复使用更长的旧文件以免残留尾部使 JSON 无效。

去重时保留资产与原始输入的关系。协议指纹可能误判，结合返回内容复核；识别出的产品名不是漏洞证据。确认 Web 服务后可交给 httpx 深入整理，模板核验交给明确选好模板的 nuclei。

## 故障与停止

- `exec format error`：核对 amd64 平台，停止，不自动切换非锁定构建。
- `-t` 后传并发数或遗漏 `-oJ` 文件名：修正参数一次，不直接套用其它扫描器命令。
- 存活判断漏掉已知资产：可在原范围内用 `-Pn` 补试一次；不扩大网段。
- JSON 解析失败：确认进程已结束、文件路径为本次新文件，并保留原始内容；不静默删除尾部或丢弃失败条目。
- 超时率高：降低并发，仅补试失败子集一次；相同错误再次出现或达到任务预算则停止。
