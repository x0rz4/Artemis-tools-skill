# 存活探测与模块选择

适用版本：**fscan 2.2.2**；Linux amd64 / arm64。依据见 [固定版本来源](references/sources.md)。

## 调用准备

先读 [Artemis 调用约定](references/artemis.md)。这个版本的 **`-h` 是目标，帮助是 `-help`**。首次了解模块用 `-list-plugins`；不同版本模块名可能变化，不照搬旧文章中的模式名。

确定本次只做存活、端口还是特定服务检测；fscan 默认 `-m all`，不能把不带模式的调用描述成仅存活探测。确认网络范围、排除项、时限和输出位置，避免重复覆盖旧结果。

## 参数选择

| 参数 | 含义 |
| --- | --- |
| `-h` / `-hf` | 目标表达式 / 主机文件 |
| `-eh` / `-ehf` | 排除目标 / 排除文件 |
| `-ao` | 仅存活探测 |
| `-m` | 从当前版本模块列表选择实际存在的模块 |
| `-p` | 明确端口集合；服务任务不要隐式扫描默认大范围 |
| `-t -time -gt` | 并发线程、超时秒数、全局超时秒数 |
| `-np` | 关闭 Ping；不能把它解释为禁用 POC 或弱口令测试 |
| `-nobr -nopoc -noredis` | 分别关闭暴力破解、POC 和 Redis 利用；不是所有模块行为的统一“只读”保证 |
| `-f json -o` | 分类 JSON 文档及输出路径 |

仅存活探测示例：

```bash
fscan -hf /work/hosts.txt -ao -t 10 -time 3 -gt 60 -f json -o /work/run-001/fscan.json -nocolor
```

选择服务模块前先读取 `-list-plugins` 输出并检查模块行为，然后明确设置 `-m` 与 `-p`。本 Skill 不预设凭据测试、远程执行或写入动作；需要不同检测行为时按实际任务单独确定。

## 读取结果

`-f json` 的最终文件是完整对象，包含 `scan_time`、`summary` 及可能省略的 `hosts`、`ports`、`services`、`vulns` 数组。数组元素具有 `time`、`type`、`target`、`status`、`details`；details 随模块变化，不假设所有条目都包含端口或漏洞编号。

**最终 JSON 在关闭输出器时汇总写入**。运行中的 `.realtime.tmp` 是恢复用 NDJSON，不能把它当作已完成的最终文档。被中断时保留原文件与临时证据，报告部分完成；不要自行删备份或伪造汇总。

按结果类别整理，存活不等于所有服务开放，vulns 类别也仍需结合具体模块证据复核。Web 端点可按实际结果交给 httpx；避免对已完成的范围无条件重复完整扫描。

## 故障与停止

- `-h` 报缺少值：这是目标参数，查看帮助应调用 `-help`。
- 不支持的参数：对照固定版本；此处用 `-np`，不猜测 `-no-ping` 等别名。
- Ping 无响应：报告发现方式的局限；已有明确存活目标时可在后续指定检测中选择 `-np`，不能将空结果直接认定为全网离线。
- 超时或资源紧张：降低并发，只对失败子集补试一次；相同错误再次出现、达到全局时限或任务预算即停止。
