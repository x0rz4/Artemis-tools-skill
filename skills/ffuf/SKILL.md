# 字典发现与响应过滤

适用版本：**ffuf 2.3.0**；Linux amd64 / arm64。依据见 [固定版本来源](references/sources.md)。

## 调用准备

先读 [Artemis 调用约定](references/artemis.md)。需要一个明确的替换位置、已存在且来源明确的字典，以及本次独立输出文件。工具包不附带所有字典；缺失时报告依赖，不临时从不明来源下载。

先确认请求方法、字典规模和任务预算；不要把内容发现自动扩展成凭据猜测或漏洞利用。默认配置文件也可能影响过滤和请求，应先确认其内容。

## 参数与示例

| 参数 | 选择依据 |
| --- | --- |
| `-u` / `-w` | URL 中的 `FUZZ` 对应字典；自定义关键词需两端一致 |
| `-mc` | 匹配状态码；`all` 保留全部状态供后续观察 |
| `-fc -fs -fw -fl` | 排除状态码、响应字节数、词数、行数 |
| `-ac` | 自动校准，会产生额外探测请求；适合确认存在通配响应的场景 |
| `-rate -t -timeout -maxtime` | 请求速率、并发、请求超时秒数、整体秒数上限 |
| `-of json -o` | 完整 JSON 文档输出，不是 JSONL |
| `-noninteractive` | 非交互执行，适合平台调用 |

```bash
ffuf -u https://app.example.com/FUZZ -w /work/paths.txt -mc all -rate 5 -t 2 -timeout 10 -maxtime 60 -noninteractive -of json -o /work/run-001/ffuf.json
```

先用小字典观察状态、长度和词数分布。若无效路径也返回同一页面，再选择经实际响应验证的过滤条件；不要凭习惯过滤全部 403 或所有相同长度结果。自动校准也可能隐藏真实响应，需要保留所用配置。

## 结果处理

一次解析整个文件，遍历顶层 **`results`** 数组；每项关注 `url`、`status`、`length`、`words`、`lines`、`input`、`redirectlocation`。报告使用的过滤条件、命中数和原始文件位置。

200 或 302 不是目录存在的充分证据；比较内容特征并复核少量代表项。保留重定向位置但先检查范围再跟随。输入文件截断、超时结束和正常空结果需要分别记录。

## 故障与停止

- 缺少 `FUZZ` 或字典路径错误：检查 URL 与字典定义，修正一次后再执行。
- 全部命中同一页面：分析通配响应，调整一组过滤条件后小批复核，不直接增加字典规模。
- 429、认证失效、持续网络错误：停止；必要时降低速率，只在预算内补试一次。
- JSON 不完整或任务被中断：保留原文件和错误记录，标记部分结果，不能补写虚构的完成状态。
