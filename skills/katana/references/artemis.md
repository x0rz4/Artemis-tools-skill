# Artemis 调用约定

Skill 提供使用知识，不自动安装工具或改变 Agent 绑定。调用前从当前工具定义确认真实 key、schema、版本、启用与可见性；用户可以改 key，不能只按工具名称猜测。

## 参数传递

本 Skill 的代码块是 CLI 参考，示例路径和目标需要替换，输出目录需预先存在。优先把每个选项映射到已注册工具支持的结构化字段。

当前 Artemis 默认 command 模板是 `'<binary>' {args}`，渲染时对整个 args 字符串做 shell 引用。因此 `{"args":"-l /work/hosts.txt -json"}` 会成为一个参数；传字符串数组也会被序列化成一个 JSON 参数，不等于 argv。单独 `{"args":"-help"}` 或对应工具的帮助开关没有多参数问题。

如果现场只有这个薄封装，停止多参数调用并报告需要维护者配置具名参数模板或修复适配层。不要用 eval、嵌套 shell、拆引号或重新注册工具绕过参数边界。不要把整段 CLI 塞进 args 后宣称已运行成功。

例如管理员可将模板配置为 `'<binary>' -l {input} -o {output}` 并定义 input/output 为字符串；调用时提交两个字段，渲染器分别引用它们。该示例仅说明适配机制，实际选项以各工具正文为准，Skill 本身不修改配置。

## 运行与结果

沿用平台既有的任务范围、审批和审计。缺少工具、绑定或平台支持时准确报告，不自行下载安装 latest、不扩大目标范围。示例速率是可调整的保守起点，最终遵循任务限制。

记录工具/资料版本、输入规模、选项、退出状态、结果路径与覆盖缺口。原始结果留文件，只提取必要的统计与证据；凭据、完整响应和大量终端日志不进入简要汇报。修正或补试限于正文规定的一次，第二次同类错误停止。
