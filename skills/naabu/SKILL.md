# 端口探测

适用版本：**naabu 2.6.1**；Linux amd64 / arm64。参数、输出依据见 [固定版本来源](references/sources.md)。

## 调用准备

先读 [Artemis 调用约定](references/artemis.md)。输入使用主机/IP 列表，明确端口集合；不要把含路径的 HTTP URL 当主机列表。容器网络出口和目标可达性可能不同于宿主机。

优先使用 CONNECT 方式；SYN 模式的权限和抓包依赖必须由部署环境提供。即使选择 CONNECT，二进制仍可能要求系统安装 libpcap；加载器报缺少共享库时不能靠增加权限修复。

## 参数与示例

| 参数 | 含义 |
| --- | --- |
| `-l` / `-host` | 主机文件 / 目标主机 |
| `-p` | 明确端口或区间；未指定时有默认端口范围 |
| `-s c` | CONNECT 扫描；不要套用 Nmap 的参数拼写 |
| `-rate` / `-c` | 发包速率 / 内部并发 |
| `-timeout` | 该版本源码按 duration 解析；显式写 `2s`，避免无单位值歧义 |
| `-retries` | 端口扫描重试次数 |
| `-json -o` | JSONL 结果文件 |
| `-Pn` | 跳过主机发现；只在发现阶段漏掉已知目标时按需选择 |

```bash
naabu -l /work/hosts.txt -p 80,443,8080 -s c -rate 30 -c 5 -timeout 2s -retries 1 -json -o /work/run-001/naabu.jsonl -duc
```

显式列端口能避免无意扩大范围。不要默认启用 Nmap 联动或被动外部查询；它们具有额外依赖和网络行为。仅端口探测时不要自动加入服务深度探测。

## 结果处理

按 JSONL 读取 `ip`、`host`、`port`、`protocol`、`timestamp`，可选服务字段可能不存在。以 IP、端口、传输协议去重并保留原主机映射。端口开放不是服务型号证据；不能把所有结果直接冠以 HTTP。

对预期 Web 端口生成保留端口的候选地址，交给 httpx 确认；IPv6 地址构造 URL 时使用方括号。其它端口按实际需要进行协议识别，不默认执行其它扫描器的完整扫描。

## 故障与停止

- 缺 libpcap、权限不足或错误架构：记录部署问题并停止；不要反复切换参数、自动安装依赖或提权。
- 主机发现没有响应：若已知范围内目标可达，可选择 `-Pn` 后仅补试一次；它不改变目标范围。
- 高丢包或超时：降低速率并对未完成的子集补试一次，相同错误再次发生则停止。
- 空结果：区分“本次指定端口未发现开放”与网络/权限失败，保留指定端口和错误信息，不能推断主机全部端口关闭。
